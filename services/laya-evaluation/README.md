# Synthetic LAYA evaluation

This is a qualification aid, not an activation tool. The evaluation client does not change clinic,
provider, KB, database, routing, service, or calibration settings. A passing report
does **not** authorize activation. `activationApproved` is always `false`.

## Scope

The bundled corpus contains 30 original synthetic examples: 15 calibration and
15 held-out examples across English, Spanish, and mixed-language requests. It
covers administrative intent, workflow branch selection, and relevance to
synthetic KB passages. It includes negation, ambiguous input, a prompt-injection
example, and questions whose answers are absent from the supplied passages.

These are starter examples, not representative clinical validation. No patient
records or real clinic knowledge are included. `synthetic: true` is a declaration,
not a patient-data detector; review any replacement corpus before using it.

## Run

Use the approved runtime host. The CLI only contacts `127.0.0.1:8767` and does not
follow redirects or use environment proxy settings. It cannot target a public
host. It imports only the adjacent wire validator, not the model or runtime.

```sh
python3 services/laya-evaluation/evaluate.py \
  --split calibration \
  --model-version laya-multilingual-e4e9ddf21a7b \
  --calibration-version upstream-unqualified-v1
```

Run `--split heldout` separately only after fixing the evaluation protocol and
candidate calibration on the calibration split. Do not tune thresholds on the
held-out answers or repeatedly relabel them to improve the score. A `null`
expected answer requires abstention. The current unqualified calibration pin
does not become reviewed merely because it is supplied to this command.

The client deadline is 1.5 seconds. This does not extend the runtime's existing
750 ms inference deadline. A runtime deadline failure must be investigated;
rerunning this tool is not a way to make the underlying inference finish sooner.

Requests are sequential. The runner stops on the first unavailable, invalid, or
timed-out response, without retrying: native computation can continue after an
HTTP timeout. Do not immediately rerun after a timeout or assume `/ready` means
the inference slot is free. Establish that previous work has settled first.

## Interpret evidence

- Exit `0`: all selected cases returned valid, pinned responses and matched the
  expected choices/abstentions. This is not a production-readiness verdict.
- Exit `1`: a mismatch, unavailability, invalid response, or timeout occurred.
- Exit `2`: invalid corpus or command configuration.

Reports include corpus version/hash, model/calibration pins, task/language
groups, elapsed HTTP time, choices, raw scores, abstentions, and correctness.
They omit request text and candidate labels. Keep identifiers synthetic too.
An incomplete group's accuracy is `null`; it must not be reported as a passing
accuracy measurement. Completed subgroup results do not make an incomplete
overall run complete. Raw scores are **not calibrated confidence**.

Elapsed HTTP time is not completed native inference time. An HTTP 503 at 750 ms
does not show how long the native model eventually took. Before clinic use,
separately establish completed inference latency, sustained resource/concurrency
behavior on the actual ARM64 host, calibrated task/language thresholds, safe
abstention and baseline fallback, tenant isolation, and existing-chatbot
regression results. Follow the approved deployment path for runtime changes;
do not edit installed artifacts or weaken isolation to obtain a passing score.

## Local harness tests

```sh
python -m unittest discover -s services/laya-evaluation -p 'test_*.py' -v
```

Tests use scripted loopback responses, not a real model. They test the runner's
wire validation, pinning, deadline, fail-fast behavior, scoring, corpus boundaries,
and report redaction. Passing them proves neither model quality nor deployment.

## Scripted conversation tester on the existing AWS host

`conversations.py` supplies four original, synthetic three-turn scripts (12
decisions) in English, Spanish, and mixed language. Each request includes only
past scripted context and the current customer turn. Assistant lines are fixed,
not generated by a Docmee workflow. Expected answers are never sent to the model.
Reports omit transcript text. This is **route replay, not an end-to-end workflow
or WhatsApp delivery test**; it reads no patient conversations and sends no messages.

The fixed-target operator `send-conversation-tests.ps1` installs sealed tester
assets under `/opt/docmee-laya/diagnostics/descriptions-20261023-a`. It requires
the non-root `DocmeeDeployOperator` AWS identity. Through SSM, it temporarily
replaces only the isolated LAYA service entrypoint with a synthetic-request-only
probe. The current experiment compares baseline and distinct route descriptions,
retaining model artifacts and resource/security limits. During this bounded test,
ordinary LAYA requests are refused and must use Docmee's existing fallback.

The probe permits four seconds for diagnostic inference; this is **not** a
production latency change. The operator restores the original entrypoint and
750 ms deadline in its `finally` path, checks unchanged app/Caddy processes and
build, and leaves redacted reports beside the installed tester. A forced machine
shutdown or operator termination can interrupt restoration; check the exact
systemd override and runtime health before any recovery. Never blindly rerun a
failed operation. The fresh-directory precondition intentionally prevents reruns
over previous evidence.

```powershell
pwsh -NoProfile -File services/laya-evaluation/send-conversation-tests.ps1
```

Poll the returned SSM command ID to a terminal status, then independently check
the public application health endpoint. The operator's exit zero means both
comparisons completed and restoration checks passed, **not** that all routing
answers were correct. Production activation and full workflow correctness are not implied.

### Frozen current-turn experiment

Both formats run the original 12 calibration turns and 12 new held-out turns,
sequentially (48 decisions total). Held-out text was frozen before real-model
testing; expected labels never enter model requests. Do not tune on these answers.
The current-turn adapter is an exact-allowlist diagnostic parser, not a general
conversation parser. It removes history, transcript framing, and the transcript's
explicit current-turn routing directive. Candidate descriptions, model question
instructions, and model weights remain unchanged. This is a combined ablation,
so any improvement cannot be attributed to history removal alone. One unseen
follow-up deliberately needs history.

Hypothesis: removing earlier intents reduces intent-switch errors. Risks include
losing coreference and useful conversation context. Before the experiment, the
candidate evidence target is no calibration regression, at least 11/12 unseen
correct, no missed human-handoff request, and successful runtime restoration with
unchanged Docmee health. These small-sample targets cannot qualify production use.
Latency must be reported against the unchanged 750 ms production deadline, even
when the diagnostic four-second deadline permits a correct answer.

### Local FP32 comparison harness (not executed on AWS)

`onnx_compare.py` validates paired output shapes and finite values, excludes
masked padding from logit differences, and fails parity on any winning-marker
or action change even when the numerical drift is within tolerance. Absolute
tolerances follow the reviewed upstream raw-output tests: logits `1e-3`, action
logits `1e-2`. Reports contain aggregate errors and paired raw-model timing,
never input text or raw logits. Incomplete, invalid or inconsistent report data
cannot produce a passing summary.

`onnx_probe.py` is an experiment library with **no automatic launcher**. Its
native function verifies the existing exact multilingual artifact manifest
before and after execution, requires the reviewed LAYA/PyTorch versions, sets
offline flags, exports FP32 opset 18, and compares three deterministic synthetic
tensor shapes with three measured pairs per shape. These exercise dynamic
batch/sequence/marker dimensions and padding, not conversational accuracy.
CPU execution is sequential with one intra/inter-op thread. The exporter uses
explicit `dynamo=False` with `dynamic_axes`; it does not rely on the PyTorch
2.14 default exporter mode. Output is confined to a newly created experiment
directory outside the model tree, leaving the original checkpoint retained.
No INT8 conversion, package installation, service configuration or runtime
promotion is implemented.

Local verification commands (dependency-free tests):

```powershell
py -3.14 -B -m unittest discover -s services/laya-evaluation -p 'test_*.py'
py -3.14 -B -m unittest discover -s services/laya-runtime/tests -p 'test_*.py'
```

These unit tests cover validation and configuration only. They do not execute
PyTorch export, ONNX inference, Linux isolation, model loading or patient-like
conversations. Windows may skip the symlink-creation test when the OS denies
symlink privileges. Target Python 3.12/native ARM64 execution remains untested.

Before invoking the native function, prepare and review an ARM64 wheel lock
for ONNX and ONNX Runtime and a separate externally CPU/memory/time/storage/
network-capped operator. The library enforces offline library settings but is
not an OS network sandbox or a resource limiter. The server's existing runtime
must not be reused as the export environment. Export peak memory and shared-host
impact remain unknown. A successful raw-tensor comparison would still require
Choice/Noul/Score wire-contract parity, uninstrumented end-to-end timing at the
unchanged 750 ms deadline, sustained-load/fallback tests, and a fresh frozen
English/Spanish/mixed-language evaluation before any routing activation.

Every comparison report explicitly keeps `accuracyImprovementProven`,
`productionDeadlineQualified` and `runtimePromotionApproved` false. No native
graph or speedup measurement has been produced by this local implementation.
